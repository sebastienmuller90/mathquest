# Finot Académie — Vérification de conformité aux exigences officielles des stores (novembre 2026)

Date de consultation de toutes les sources : **04/11/2026**. Base du dépôt : `main@1e7bbd0`.
Ce document confronte ce que **le dépôt déclare** à ce que **les pages officielles Google et Apple affichent**. Ce n'est pas un avis juridique.

Légende de l'état : **CONFORME** (démontré par un fichier du dépôt cité) · **NON DÉMONTRÉ** (rien dans le dépôt ne le prouve, ou dépend d'une action humaine/console) · **À CORRIGER** (écart ou risque identifié).

Limites de la vérification (à lire) : les pages ont été lues via un outil de récupération qui résume le contenu ; deux pages Apple (accord Apps payantes, première URL des spécifications de captures) et une page Google (déclaration « trader ») ont renvoyé une erreur 404 et n'ont donc **pas** pu être vérifiées. Les points issus de ces pages sont marqués « source non confirmée ». Les montants de commissions et le statut précis des exigences Apple postérieures à avril 2026 sont à **revalider directement dans les consoles** avant décision.

## 3. Écarts entre la documentation du dépôt et les exigences officielles

1. **Aucun écart critique bloquant la V1 Android** : cible API 36, AAB, Sécurité des données sans collecte, assets et plan 12/14 sont cohérents avec les pages consultées.
2. **Vérification des développeurs Android (G13)** : absente de la documentation ; à ajouter aux étapes de soumission.
3. **Statut « trader » / DSA (G14, A12)** : absent ; point juridique à trancher avant l'inscription (affichage public d'adresse et de contacts).
4. **Permission `INTERNET` sans usage actif** : cohérente avec le suivi parent futur et expliquée dans `play-console-answers-draft.md`. Si l'on veut le minimum strict, elle peut être retirée tant que le suivi distant n'est pas activé (décision produit, hors périmètre de cette mission documentaire).
5. **Âge ciblé 6–15 ans vs Catégorie Enfants Apple 5–11 ans (A6)** : à arbitrer avant toute soumission iOS.
6. **Aucune documentation iOS dans ce dépôt** : ne pas supposer la conformité iOS.
7. **Code parent = barrière d'usage, pas un secret fort** (empreinte 32 bits, `families-compliance.md` ATTENTION 1) : suffisant tel quel, mais à renforcer avant d'y adosser un **achat** (voir architecture V1.1).
8. **Date périmée** : la prolongation du niveau d'API (01/11/2026) est échue ; la règle s'applique sans délai supplémentaire.

## 4. Actions humaines indispensables (liste ordonnée)

1. Ouvrir/valider le compte développeur Google Play (identité légale, adresse, vérification), confirmer le **type de compte** (personnel ou organisation) pour savoir si le test fermé 12/14 s'applique, et décider du statut **trader/non-trader** (DSA) avec un conseil juridique.
2. Vérifier en Console l'enregistrement du nom de paquet / la vérification de développeur Android (G13).
3. Créer et sauvegarder (hors Git) la clé d'upload ; téléverser l'AAB signé en test interne ; contrôler le manifeste fusionné (aucune `AD_ID`, permissions attendues).
4. Publier et tester sans authentification l'URL de la politique de confidentialité ; la reporter dans la Console et dans l'espace Parents.
5. Remplir en Console : audience cible (6–8, 9–12, 13–15), classification IARC, Sécurité des données, ID publicitaire = non, publicités = non, achats = non, accès à l'app.
6. Téléverser les visuels finaux (icône 512, feature graphic 1024×500, ≥ 2 captures téléphone, captures tablette) après contrôle des dimensions et de l'absence d'alpha.
7. Recruter 15 à 18 testeurs, mener le test fermé 14 jours continus si exigé, puis déposer la demande d'accès production.
8. Décider **si et quand** viser iOS : compte Apple Developer, Xcode 26+, `PrivacyInfo.xcprivacy`, questionnaire d'âge, App Privacy, captures iPhone/iPad, arbitrage Catégorie Enfants, argumentaire guideline 4.2.
9. Revalider les points « source non confirmée » et les commissions directement dans les consoles le jour de la décision.
10. Ne rien ajouter (monétisation, publicité, SDK tiers) sans relire `docs/monetization/architecture-v1.1.md` et sans nouvelle passe Familles / Sécurité des données / App Privacy.
